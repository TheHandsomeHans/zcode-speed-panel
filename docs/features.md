# Feature Details

Precise behavior and specifications of currently implemented features. Verify against this document before changing any feature (it should stay in sync with the code); user-facing descriptions can be found in `README.md`.

## Data and Statistical Specifications

- **Today's Total** = `input + output + reasoning + cache_creation` (matches ZCode's official statistics); **cache hits (cache_read) are prompt reuse and not counted in the total**, displayed as a hit rate: `cache_read ÷ (input + cache_creation)`. Note that the usage DB's `input` is itself the total prompt tokens including the cache-hit portion (in `raw_usage_json`, `totalTokens = inputTokens + outputTokens`; across the whole DB, `cache_read ≤ input` and `cache_creation = 0` proves this). The denominator must not add `cache_read`, otherwise it double-counts and the hit rate gets diluted by roughly half (once showed 98% as 49%).
- **Average Speed avg_tps** = Σ(output+reasoning) ÷ Σ pure generation time; denominator uses `completed_at - first_token_at` (excludes first-token wait/queuing); `first_token_at` missing falls back to `duration_ms`, lower bound 50ms.
- **Last-Call Speed last_call_tps** = the (output+reasoning) of the call with the latest completion time ÷ its pure generation time (same spec as average speed but only looks at the single most recent call, not a real-time IO reading); 0 when there are no completed calls today. Uses "latest completion time" rather than the last ingest-order row so DB query ordering changes don't affect results.
- Today's attribution is by call completion time; automatically resets at day rollover.
- Data source: `model_usage` table in `~/.zcode/cli/db/db.sqlite`, opened read-only (WAL does not affect a running CLI).

## Real-Time Speed (liveio.rs)

- Cleaned pipe byte rate over the intersection of the 30s sliding window and active segments ÷ self-calibrated coefficient (bytes→token).
- **Multi-task concurrent aggregation (multiple windows / sub-agents in parallel)**: the gate returns **all** in-progress sessions; real-time speed = aggregated stream over the **union** of each session's attributed processes (`merge_streams`: same-tick bytes summed, wall-clock duration counted once, tracked file growth deducted once overall) — the current reading is the true **total throughput**, no longer "that one session of the latest in-progress row". When any in-progress session has no attribution record yet (new session / sub-agent's first call not completed), it falls back to **all-process sum** as a safety net (`pick_pid_set` returns None: can't miss a new process and show another window's speed; idle processes contribute ≈ 0 after noise cleaning). Multiple sub-agents in the same process can't be split at the byte level and are counted as that process's combined total.
- **Platform primitives** (`liveio::platform`, three cfg-gated implementations: win / mac / stub; examples share the same path):
  - **Windows**: Toolhelp32 enumeration + filter `zcode.exe` command line containing `zcode.cjs`; `GetProcessIoCounters` `WriteTransferCount` for cumulative write bytes; tracked files (rollout/logs/WAL) total scanned for disk-write deduction.
  - **macOS**: `proc_listallpids` enumeration + `KERN_PROCARGS2` command-line parameter exact match for `zcode-cli` (the CLI is forked from Electron Helper; the executable path is shared with other Helpers, proc_pidpath can't distinguish them — measured CLI process parameter area has a standalone `zcode-cli` string); `proc_pid_rusage(RUSAGE_INFO_V4)` `ri_diskio_byteswritten` for cumulative disk write bytes; the handle captures `ri_proc_start_abstime` when opened to guard against PID reuse (mismatch = process exited, remove); **no tracked file deduction** — measured rollout directory `du` net change can be negative (CLI cleans up rotation), negative increments would backfeed and inflate the cleaned stream, and being constantly 0 avoids per-tick directory scanning. `rusage_info_v4` is a per-field `#[repr(C)]` mirror; key field offsets (start_abstime=80, diskio_byteswritten=152) are pinned by `offset_of!` compile-time assertions; SDK layout changes fail compilation outright.
  - **Other platforms**: stub (empty list / None); panel falls back to window/estimate display.
- **CleanParams platform parameter table** (cleaning/calibration parameterization, `CleanParams::platform()` locked at startup; Windows column = long-term measured original values — do NOT change; mac column = 120s probe initial values — **must be verified by measurement**):

  | Parameter | Windows | macOS | Reason |
  |---|---|---|---|
  | burst_tick_bytes (burst rejection) | 100_000 | u64::MAX (disabled) | mac streaming IS single-tick bursts (225KB~1.5MB normal); 100KB threshold would discard all signal |
  | base_noise_bps (static noise floor) | 3_000 | 0 | mac idle measured strictly 0 bytes over 17s |
  | floor_cap_bytes (adaptive noise floor cap) | 2_000 | 2_000 | cap only prevents poisoning; mac idle constantly 0 makes adaptive drop to 0 on its own |
  | default_bpt (coefficient prior) | 600 | 700 | mac true-value reconciliation (2026-09-17, 6 cal events) accepted samples 614/724; old value 2000 came from probe misjudgment, cold start 3x underestimate |
  | cal_min / cal_max (sample range) | 100 / 6_000 | 100 / 12_000 | mac covers measured reconciliation ~650 with headroom |
  | cal_min_tokens (sample threshold) | 300 | 300 | platform-independent |
  | detect_ms (anchor detection window) | 2_500 | 2_500 | v1 unchanged; mac if state jitter, adjust to 5_000 |
  | cal_grace_ms (delayed disk-write grace) | 0 (process same tick) | 15_000 | mac's `ri_diskio_byteswritten` is asynchronous page-cache disk-write counting, lagging `write()` by seconds to tens of seconds (measured 117s call: 96% of bytes land after `completed`); after call completion wait for full grace before integrating; calibration integral and raw stats window upper bound extended to `completed+grace` same time; numerator/denominator same spec |
  | cal_outlier_ratio (sample outlier rejection) | 0 (disabled) | 3.0 | sample B/token deviating from current active coefficient by more than 3x is rejected: partial delayed-disk-write samples (measured 186, too low, pollutes median) and attribution-anomaly samples don't enter the median |

- **Start/stop gate**: the usage DB message table's assistant message row — submitted the instant the call starts (readable within ≤200ms); the row's `time.completed` is backfilled at the end (**including cancellation/error**). Scans recently active sessions (`session.time_updated` descending, top 16 — multi-task aggregation needs to cover all in-progress sessions; >6 concurrent sub-agents can't be missed; each uses the `(session_id, time_created)` composite index to fetch the latest assistant row): among them, the **all** sessions whose latest row has no `completed` and are within 10 minutes are considered in-progress (in start-time descending order; concurrent tasks each counted; a new conversation's first call lights up the same tick); has `completed` → reset to zero same tick. When the attributed process of an in-progress session **all** exits, force-stop (safety net for zombie rows where crash leaves no one to backfill `completed`; unattributed sessions are not force-killed). **Stop safety net (`stale_stop`)**: CLI's `completed` backfill can be delayed by seconds to minutes; during that time the window fallback keeps showing "Generating + ≈ last-call speed" — once a streaming anchor appears, if the cleaned stream rate (detection window spec) stays below the streaming threshold for 15s (`SILENT_STOP_MS`), it determines generation has stopped and resets the reading to zero; calls with no anchor established (silent-pipe calls) are unaffected; on misjudgment, byte recovery self-heals the same tick. After stream break then resumed stream (stop was triggered), re-anchor; the 30s sliding window starts fresh so the silent segment doesn't dilute it.
- **Per-task details (`snapshot.tasks`)**: during streaming, gives real-time speed per CLI process (`LiveNow.tasks`; file growth allocated by each process's **positive** byte share — negative-tick processes don't participate in allocation, values clamped to 0, ensuring the sum of details isn't inflated by negative ticks). **Total tasks = Σ each row's `n_sessions` (unattributed rows count 1)**; when ≥ 2, the full panel shows a "Concurrent Tasks" card between the gauge row and the chart: status point reuses live/idle styling, values colored by `SPEED_TIERS` tier, session label = last 6 chars of attributed session id (unattributed shows "unattributed process pid"; **a process hosting multiple sessions counts as one combined row**, labeled "N sessions (combined)" — new tasks opened in the same ZCode window reuse the same app-server process, can't be split at byte level); hidden only after 3 consecutive ticks (~2s) with total tasks < 2 (1↔2 boundary debounce). **Pet** bubble expands task rows when total tasks ≥ 2 (one row per process: last 6 chars of session / process pid + tier-colored speed; non-streaming shows "Idle"; backend simultaneously grows the pet window upward by 96px to make room, see "Floating Window & Pet"); **Mini gauge / pill still only show the aggregated value**; `live_source=window` (≈ fallback), startup (TTFT), and idle all have empty tasks. Attribution has concurrent deduplication (`pick_attribution`: if the top process is already claimed by another in-progress session and the second-highest bytes reach half of top, reattribute to the second-highest to prevent tie mis-attribution from squeezing two sessions into the same pid, see key-rules #13).
- **Startup prompt (is_starting)**: gate open but first byte not yet arrived (TTFT, within 20s window; for concurrent sessions, counted from the **most recently started** session) → gauge face / mini gauge / pill / pet bubble shows **"…"** (cyan breathing pulse arc), no estimate displayed; if window passes with no bytes → treated as silent-pipe call, falls back to ≈ estimate.
- Status source `live_source`: `io` (measured streaming) → `window` (gate says generating but pipe silent; shows true speed of recently completed calls, frontend adds ≈ marker) → `idle` (zeroed).
- **When IO is unavailable** (processes never discovered: probing environment unavailable / just started) the gate shows an estimate or "Collecting…" instead of blind estimation by call interval; **after all CLI processes exit**, zero immediately (old behavior could idle-spin "Estimating" for up to 240s by interval median).
- After first byte, readings are available the same tick (previously the TTFT "…" prompt); process discovery: normally 30s refresh, shortened to 2s when no process exists, when an in-progress session without attribution record exists (a newly opened second window — during safety-net period you'd be reading another window's speed), or when ≥ 2 in-progress sessions exist (multi-task concurrency, attribution dedup needs to see new process byte distribution quickly).
- Coefficient cold start = 600 (mac 700) prior; converges after 1–2 calls ≥ 300 tokens; silent-pipe calls don't enter samples (see key-rules #5). **Coefficient sample persistence**: queue written to disk on change (sample entry / recalibration) to `~/.zcode/speed-panel-cal.json` (`updated_ms` + `samples`); restart / hot restart hot-start (active coefficient = median of restored queue, same spec as calibration path; out-of-range samples rejected); missing file / corrupt / older than 14 days (old model-change samples are stale noise) falls back to prior and re-converges — previously every restart started from prior 600; sessions where coefficient truth diverges from prior (measured high-speed tier ~160) had restart readings 2–3x low, converging in ~25 minutes. After recalibration, the queue [prior] is likewise written to disk; "recalibration intent" is preserved across restarts.
- **Recalibration (manual + drift auto)**: `LiveIo::reset_calibration` discards learned coefficient samples and returns to the platform prior's cold-start state (pending calls retained to maintain session→process attribution; their old-magnitude samples are squeezed out by the sliding window in 1–2 rounds). ① Manual: full panel current-speed card top-left ⟳ button (`recalibrate` command); ② Auto (round-avg-speed drift, `liveio::RoundDrift`): one round = one continuous segment of gate "in-progress" signal (adjacent calls with no idle ticks are merged into one round); round average = arithmetic mean of displayed speeds where `is_live` and > 0 in that segment (silent-pipe / estimate rounds have no measured ticks, don't participate); if the last round's average differs from the previous 5 consecutive round averages by ≥ 3x (both directions, `DRIFT_ROUNDS`/`DRIFT_RATIO`), a magnitude jump (model / tokenizer changed, old coefficient expired) is detected and auto-triggers; drift history is cleared and re-accumulated after triggering. **Multi-process aggregated rounds don't participate in drift detection** (any single measured tick in the round covering > 1 process skips the whole round): throughput differences from task-count changes are not coefficient drift; 1 task at 40 t/s and 3 tasks at 120 t/s use the same coefficient. Both trigger types write `cal_reset` debug log and emit `recalibrated` event to the frontend (button flashes ✓).
- **Delayed disk-write grace & outlier rejection (mac)**: after call completion, pending calibration events wait the full 15s before processing (`cal_grace_ms`, Windows=0 = process same tick); calibration integral and raw stats window upper bound extended to `completed + 15s` (`stream_start` lower bound unchanged, still `completed − min(gen_ms, 300s)`; pred_tps spec unchanged, denominator still uses real gen_ms); samples whose B/token deviates from the active coefficient by more than 3x are rejected (`cal_outlier_ratio`, Windows=0 = disabled) to prevent partial delayed-disk-write samples and attribution-anomaly samples from polluting the median. cal log includes `attr_pid` (process actually used for the clean integral; null for the all-process-sum branch) and `top_pid` (raw top process) for attribution anomaly diagnosis.
- **Attribution & sample admission concurrency guard**: session→process attribution has **switch hysteresis** (`should_reattribute`: when already attributed, the candidate process must have window-raw-bytes ≥ 2x the current attribution within the call window to switch, preventing per-call flipping between concurrent windows; if the current attribution's window-raw-bytes are 0, trust top directly for self-heal; attribution establishment threshold is window-raw-bytes > 20KB); calibration samples additionally have a **cross-process guard** (`cross_pid_ok`: if another process's window-raw-bytes > 20% of the baseline process, reject — the other window's concurrent streaming would inevitably mix foreign bytes into the integral. Baseline = attributed process; the unattributed all-process-sum branch uses the top process as baseline, that branch also can't pass); cal log `others_kb` for diagnostics; `cal_sample`'s clean/raw ≥ 0.2 guard numerator/denominator are **paired** (when clean comes from the attributed process, raw also uses that process's bytes, not all-process raw).
- Accuracy: qualifying calls `pred/true` should be within 0.8–1.25 (measured 1.00–1.05); reconciliation command `python scripts/live_vs_true.py`.

## Network Monitoring (netio.rs)

Full panel "Network Monitor" card (default ordered below the gauge row; visibility and order adjustable in the top-bar ⚙ settings, see "Module Visibility & Ordering" section. Single row, three horizontal sections: speed on the left · process connection count in the middle · today's upload/download on the right; narrow windows auto-wrap; `main` has an additional fallback scroll; on platforms where interface counting is unavailable the whole card is hidden). Monitors ZCode's upload/download traffic and distinguishes **session traffic** (API dialog traffic carried by CLI processes) from **non-session uploads** (snapshot uploads from the Electron desktop app, etc.), following the 2026-09-17 discovery that ZCode encrypts and uploads the entire workspace (including full `.git/` history) to Alibaba Cloud OSS (single artifact measured at 549MB). **As of 2026-09-20, all snapshot-related UI (protection toggle / today's snapshot uploads / snapshot upload record list) moved to the "Snapshot Protection & Upload Log" card below** — module name and content correspond; this card only retains the network traffic itself; the snapshot layer's data-fetching spec is unchanged (still fed by netio.rs).

### Why Tiered Specs (Platform Limitations)

**Windows has no public per-process network send/receive byte primitive under non-admin**, a 2026-09-18 local experiment conclusion (see key-rules #15 for detail):

- Winsock send/receive bytes do **not** enter any `GetProcessIoCounters` counter (during a 20MB download, `ReadTransferCount` was only 7.8KB) — process IO counters only cover files / pipes / devices, so liveio's streaming speed measurement is naturally immune to network pollution;
- TCP ESTATS (`Set/GetPerTcpConnectionEStats`, the only per-connection byte API) is unavailable — 2026-09-18 re-verification archived (`python scripts/estats_probe.py`, build 26200, normal privileges): all 4 exported symbols (v4+v6) exist, but `Set` (to enable Data collection) returns `ERROR_ACCESS_DENIED`(5) for both own and others' connections (enabling requires privilege, unrelated to connection ownership); with collection disabled `Get` always fails (`ERROR_INVALID_USER_BUFFER`(1784) mostly, a few `ERROR_NOT_SUPPORTED`(50)); calling-convention variants (Get with Rw / Set with Rod buffer) don't change the result;
- ETW kernel network events require admin.

Therefore the implementation honestly splits into three tiers, with each item's spec explicitly labeled on the frontend UI:

| Tier | Content | Spec |
|---|---|---|
| Machine-wide upload/download speed + today's total | interface counter sum (excluding loopback) | **True value** |
| Session traffic (today's upload/download) | token count × byte coefficient | **Estimate ≈** |
| Non-session uploads (snapshot artifacts) | checkpoints `state.json` accept events | **True lower bound** |

### Machine-Wide Measurement (True Value)

- **Windows**: sum of `dwIn/dwOutOctets` for all non-loopback interfaces via `GetIfTable`. Counters are **32-bit**; must do **per-interface** mod 2³² differencing (each interface wraps at a different time; summing then differencing would break — guarded by test `wrap_delta_handles_32bit_wrap_and_resets`); a single-interface single-tick increment ≥ 2³¹ is treated as counter reset / index reuse, clamped to 0. `MIB_IF_ROW` mirror key field offsets (dwInOctets=552 / dwOutOctets=556) compile-time asserted.
- **macOS**: sum `ifi_obytes/ifi_ibytes` via `getifaddrs` (64-bit, no wrap; raw differencing, fallback clamped to 0), excluding `lo0`; each interface returns multiple rows per address family, **must deduplicate by interface name** otherwise bytes double. `if_data64` mirror ibytes=64/obytes=72 compile-time asserted (per xnu SDK layout; if mac-side SDK changes and assertion fails, verify by measurement).
- Speed = ~1s sliding window difference (aligned with Task Manager's ~1s refresh rhythm; readings jumpier than the old 10s window, expected); today's cumulative resets at day rollover, persists and continues across restarts (`~/.zcode/speed-panel-net.json`, 30s throttled disk writes + forced save on exit).
- **Meaning of machine-wide spec (explicitly labeled on UI)**: machine-wide = network traffic of **all apps on this machine** (including system / browser / proxy tunnel encryption overhead), **not just ZCode** — the speed value label states "all apps", the card's top-right states "Machine-wide = all apps on this machine (not just ZCode)", and the speed block hover tooltip has the full explanation. It answers "how much did this machine upload today", not "how much of that is ZCode" (the latter is answered by the lower two tiers); especially note tunnel-overhead amplification when going through a local proxy (ZCode → 127.0.0.1 proxy → internet).
- **Comparison with Task Manager**: Task Manager's NIC page shows **bits** (Mbps/Kbps; ×8 ≈ bytes) and only counts the **selected adapter**; this panel uses **bytes**, sums all non-loopback interfaces (virtual NIC / VPN tunnel traffic counts both inner and outer layers, can exceed single-NIC readings), and ~1s sliding window average (bursts are smoothed and sampling moments differ) — instantaneous readings not matching between the two is a spec difference, not a counting bug; noted in the UI tooltip.

### Session Traffic (Estimate ≈)

Derived from usage DB today's token count × byte coefficient (`sess_bytes_est` pure function, frontend adds ≈ label):

- **Upload** ≈ uncached prompt tokens × 5 B/token. Numerator uses `input + cache_creation − cache_read` (**cache-hit prompt portions aren't re-sent** — measured with 98% hit rate, machine-wide daily upload was only dozens of KB; estimating full resend would inflate by dozens of times).
- **Download** ≈ output+reasoning tokens × 400 B/token (SSE event stream density; 2026-09-18 measured calibration: streaming-period machine download ÷ token ≈ 731 B/token as upper bound, UI pipe coefficient bpt≈320 as lower bound; midpoint taken).

### Non-Session Uploads = Snapshot Artifacts (True Lower Bound)

Polls `~/.zcode/v2/checkpoints/*/state.json` (one tick every 2s):

- **Accept events**: `lastAcceptedManifestHash` change = snapshot artifact accepted by server; counts toward today's cumulative by `lastCompressedSize.encryptedSizeBytes` (encrypted compressed bytes); those with `recordedAt` before local today's 0:00 are not counted (day-rollover dedup guard — same hash always belongs to its recorded day). **Today's accepted artifacts carry a roster** (workspace/bytes/recorded time, capped at 100 entries, persisted with `speed-panel-net.json`, survives restarts / backfill) — the status line "Today N" lists workspace names line by line below (aggregated by workspace; when count > 1, attaches "n · byte subtotal"; latest artifact per workspace sorted nearest-first — backfill scan order doesn't guarantee time ordering, uses max recordedMs per group; hover a roster line for that workspace's today's per-item detail); copy/export report includes the same.
- **Upload in progress**: any workspace's `activeUpload` non-empty → status line pulses "Snapshot upload in progress".
- **Backfill**: on first start of the day, backfills accepts with `recordedAt` today but not observed while the panel was absent, counted by current `lastCompressedSize` (if the panel already ran today, only establish baseline, no backfill).
- **Spec is panel observation period**: accepts while the panel isn't running are only counted in the backfill above; multiple jumps between two ticks count by final state (lower bound).
- **Directory status**: `ok` / `missing` (no directory) / `blocked` (unreadable — truthful display after the user ACL-locks checkpoints; new uploads can't be monitored then).
- Events are simultaneously written to debug log (`kind:"net"`, `ev`=ckpt_accepted / ckpt_upload_start / ckpt_upload_end, with `mb` and workspace `ws`).
- **Snapshot upload record list** (inside the Snapshot Protection & Upload Log card; moved from the right column of the network card on 2026-09-20): one row per workspace = record time (today HH:MM, cross-day MM-DD HH:MM) / workspace name (last segment of workspacePath) / encrypted size / status (**Uploading ⬆ / Pending / Accepted ✓**), sorted: uploading > pending > accepted (same status by record time descending); **fixed 5-row display (row height 18px: 5×18 + 4×2 gaps = 98px height cap); remaining rows scroll inside the list** (doesn't expand the whole page; `ckpt_rows` pure function, guarded by test `ckpt_rows_sorted_all_workspaces`). The list reads checkpoint live state (`state.json` only retains each workspace's latest artifact; earlier history is unknowable); final state during panel-absent periods is visible on startup.
- **Copy & Export**: list text can be selected for copying (exception to global `user-select:none`); list header has **Copy / Export** buttons — Copy writes the full plain-text report (header + per-row records + today's summary + ZCode two-group connection live state) to clipboard (`navigator.clipboard`, falls back to `execCommand` on failure); Export uses the `export_text_file` command to write `~/.zcode/speed-panel-exports/zcode-snapshot-upload-log-date-time.txt` (filename whitelist-sanitized to prevent path traversal; bottom-right toast shows full path; browser preview mode degrades to browser download).

### ZCode Connection Attribution (True Value, Windows Only)

TCP connection table (`GetExtendedTcpTable` OWNER_PID, v4+v6, ESTABLISHED only) grouped by process. **Both groups are connections of ZCode's own processes, no other apps** (UI labels are "ZCode Session Process / ZCode Desktop", hover titles have the full explanation):

- **Session group (ZCode Session Process)**: CLI (app-server) processes whose command line contains `zcode.cjs` — the bearer of dialog API traffic; process discovery spec matches liveio; pid grouping refreshed every 5s; connection table enumerated every tick;
- **Desktop group (ZCode Desktop)**: remaining `zcode.exe` = ZCode desktop's Electron shell (main / renderer / GPU / utility / crash-reporter processes) — the bearer of **non-dialog** traffic such as snapshot uploads and telemetry.

Each connection is labeled with its **attributed process** (type label + pid; distinguished by Electron `--type` parameter: CLI session process / main process / renderer process / GPU process / utility process / crash-reporter process; `proc_label` pure function, guarded by test `proc_label_by_command_line`); each group's rows show deduplicated count by remote+pid; **hover tooltip lists each `remote ip:port · process type(pid)`**. **Evidence-chain usage**: machine-wide upload speed spiking + new connection in desktop group + `activeUpload` = on-site evidence that a snapshot upload is occurring. mac-side connection attribution not implemented (panel hides that row; interface counting still available). **Neither group shows its own speed**: per-process network bytes have no public primitive under non-admin (see "Platform Limitations" above; ESTATS re-verified); true speed is only measurable at the machine-wide tier.

## Snapshot Protection (snapshot_guard.rs + src/guard.ts)

Full panel "**Snapshot Protection & Upload Log**" card (default ordered below the network monitor card; **default hidden — only shown after checking it in the top-bar ⚙ settings**, see "Module Visibility & Ordering" section): **blocks ZCode workspace snapshot silent uploads** while being the sole UI home for all snapshot-related content — protection control area (badge / button / stats, rendered by guard.ts) + today's snapshot upload status row + snapshot upload record list (rendered by `renderSnapshot` in main.ts, data still from netio.rs; merged from the network card on 2026-09-20). When the backend has no `guard` field (browser preview / mock), the protection control area is hidden; only the record list shows.

- **Mechanism**: After ZCode logs in, it encrypts the entire workspace (including full `.git/` history) into a tar.gz written to `~/.zcode/v2/checkpoints/<workspace-hash>/pending/*.tar.gz.enc`, then uploads directly to Alibaba Cloud OSS via credentials from zcode.z.ai; the settings toggle is ineffective, and the credential API shares a domain with the model API so **the network can't be blocked** (verified locally 2026-09, [mechanism analysis article](https://blog.ferstar.org/posts/zcode-silent-workspace-snapshot-upload/)). Protection = directory write lock — macOS `chflags uchg` immutable flag (user-level, no sudo needed) / Windows NTFS deny ACE (`icacls /deny *<SID>:(OI)(CI)(WD,AD)`; deny takes precedence over all allows: the current user's create/write within the whole tree is denied, read unaffected) — ZCode can't write in, the snapshot chain is dead. **Doesn't touch the network or processes**, non-intrusive to a running ZCode.
- **Two activation modes** (confirmation dialog choice of one, 2026-09-19):
  - **Keep & Lock** (recommended): existing snapshots are **kept in place (encrypted, read-only)** and the **whole tree is recursively locked** (mac `chflags -R uchg` — uchg only locks the directory's own entry table; locking just the root won't block writes inside existing subdirectories; win inheriting deny ACE is automatically propagated by the system to existing subtrees, equivalent to recursive; key-rules #16). Upload records display normally in real time; the trailing 📂 opens the snapshot directory;
  - **Delete & Lock**: archives the record roster first, then clears all snapshots, recreates an empty directory, and locks the root — original upload records disappear (only the archive remains), the confirmation dialog states this explicitly.
  - Common cost: loss of **"Checkpoint Rollback / Timeline"** (state.json can't be updated); dialog / completion / tool calls unaffected; reversible at any time (kept-mode snapshots restore writable in-place; delete-mode empty directories auto-recreated by ZCode).
- **Card spec**:
  - Status badge 🔒 Protected (green outline) / 🔓 Unprotected, determined by **write probe** (create+delete a temp file in the directory; creation failure = locked; directory absent = unlocked);
  - Data row has three states: Unprotected = `N encrypted snapshots accumulated locally · X · covering M projects · K upload failures` (N = `**/pending/*.enc` per-file measured; K = sum of `failureCount` across all `state.json`; scan throttled at 5s; **keep-mode locking doesn't affect read-only scans**); Active·Snapshots Retained = `Protection active (snapshots retained): N read-only locked (total X)…`; Active·Snapshots Deleted = `Protection active (snapshots deleted): directory cleared and locked… (N archived entries viewable)`;
  - While active appends `P rounds of dialog since protection enabled · 0 new snapshots written` — P is post-lock dialog rounds: the `calls_today` baseline at lock time is stored in `~/.zcode/speed-panel-guard.json`; the poller accumulates by calls delta every tick and writes to disk. **The delta baseline `calls_seen` is likewise written to disk and restored on startup** (memory-only resets to zero on restart; the first tick then counts the whole day's total — measured a 15-minute inflation to 3412; delta goes through pure function `accrue_rounds`; day rollback resets the baseline tick by 0 delta); when the directory is locked but guard.json has no record (user manually locked / panel reinstalled), the first tick retroactively records the baseline.
- **Linkage with upload records**:
  - "Snapshot upload record" trailing **📂 button**: opens that workspace's snapshot directory in the system file manager (`open_checkpoint_dir` command; mac `open` / Windows `explorer`, **cross-platform**; directory name validated by `valid_hash_name` whitelist to prevent path traversal; reports truthfully if directory doesn't exist). Only rows that truly exist on disk (real-time scan) render the button — archived history rows have no hash so show no button;
  - Active protection: keep-mode banner `🔒 The following snapshots are locked & retained (read-only)` + live rows display normally and are clickable; delete-mode (scan empty) = 🔒 lock banner + **pre-protection archived rows** (`~/.zcode/speed-panel-ckpt-history.json`, status "Uploaded ✓" overall dimmed; falls back to today's roster if pre-version didn't archive); normally empty list = "No snapshot records" in gray — the list area never silently blanks in any state;
  - Today's snapshot status row (`ckpt-info`) when locked, the today's-total row is annotated "all records are from before protection was enabled" (the protection-active announcement is in the protection stats row above; no duplicate 🔒; once enabled there can be no more "upload in progress" pulses);
  - Copy/export reports in active protection (delete mode) append a "Original upload records before protection" section (forensic completeness preserved).
- **Archive-then-clear (delete mode)**: before apply deletes checkpoints, merge the current upload-record rows (each workspace's latest snapshot; reuses netio's parsing and row construction, same spec as the live list) into ckpt-history.json — newer rows for the same workspace overwrite older ones, sorted by time descending, capped at 500 rows (`merge_history` pure function, guarded by tests); repeated enable/disable/re-enable doesn't lose history. Keep mode writes no archive (records aren't destroyed).
- **Protection principle & monitoring boundary hover**: the card title hover shows mechanism explanation (land on disk first then upload → lock the directory = break the chain) plus truthful declaration of monitoring boundaries (lock state probed every tick / 0 new snapshots under known mechanism = blocking evidence / machine-wide traffic backfall but mac has no per-process attribution; a switch to direct-upload mechanism could only be detected by traffic anomalies) — does not promise 100% interception.
- **Terminology**: user-facing copy uniformly uses "snapshot / encrypted snapshot", never the internal jargon "artifact" (2026-09-18 user feedback: "don't make up names").
- **Commands**: `snapshot_guard_status` / `snapshot_guard_apply(keepFiles)` / `snapshot_guard_release` / `open_checkpoint_dir(hash)` (all registered in `generate_handler`); status is also piggybacked on every metrics payload's `guard` field. apply(keep=true) = lock whole tree (snapshots retained); apply(keep=false) = archive → clear → recreate → lock root; release = **unlock whole tree** (mac recursive nouchg / win remove deny ACE including subtree inheriting copies, compatible with keep-mode whole-tree lock) + clear counts, **files untouched**. **Confirmation dialog lives on the frontend** (`#guard-confirm`) — dual-mode buttons: "Keep Snapshots & Lock" (primary button) / "Delete Snapshots & Lock" (red danger style); the delete-mode five-point informed consent is mandatory: loss of checkpoint rollback / dialog unaffected / original upload records will disappear / auto-backup is only the roster (snapshot file details are unrecoverable after deletion) / reversible (key-rules #16).
- **Platform**: macOS / Windows dual-platform support (win uses NTFS deny ACE; FAT32/exFAT without ACL, icacls reports truthfully); on other platforms the card still displays but buttons are disabled, with "File lock only supports macOS / Windows" labeled on the right of the title (following the connection-detail precedent of truthful degradation). **📂 Open directory is an independent command, works on both platforms** (the record list itself is cross-platform). **Lock strength difference between Windows and mac**: deny ACE only denies create/write (WD/AD), intentionally excluding delete (D/DC) — measured: denying D blocks even pure-read tools that open files with DELETE permission (git-bash's POSIX unlink emulation, some editors / sandbox layers); therefore post-upload routine cleanup by ZCode can still move away old pending snapshots on Windows (no new leakage); mac's uchg even blocks deletion (key-rules #16).

## Gauges & Charts (gauges.ts)

- **Current Speed gauge**: minimum scale 60 t/s (`minScale` can be overridden per gauge); card top-left has the **⟳ Recalibrate button** (spec in "Real-Time Speed" section), echoing the top-right "Last Call" badge; **Average Speed gauge**: minimum 10 t/s; **Today's Total gauge**: minimum scale 100M tokens, auto-expands past peak (100M→200M→500M→…), slowly contracts on fallback.

Hover shows spec explanation (`title`). Size constrained by card corner padding: at minimum window width 720px, the main gauge arc is already near the corner; enlarging requires widening card padding in sync. The same small ring is used in the mini-gauge floating window (46px, see "Floating Window & Pet").
- **Current speed gauge tier coloring** (top of `gauges.ts` as `SPEED_TIERS`; shared by main gauge, mini gauge, and corner badges): background track always gray; the entire progress arc **wholly** changes color by the tier of the current speed — six tiers full coverage (some ultra-fast models far exceed 100 t/s, so the upper bound is open): 0–40 green `#34d399` / 40–80 yellow-green `#a3e635` / 80–160 yellow `#fbbf24` / 160–240 orange `#fb923c` / 240–320 red `#f87171` / 320+ magenta `#e879f9`; large number changes color in sync; idle (0) number stays default white; estimate state stays amber ≈, not tier-colored.
- Scale follows the peak smoothly (peak rises, immediately expands; falls back, exponentially converges); during estimate the pointer/arc turns amber and adds ≈; **startup (is_starting) the number shows "…" with a cyan short-arc breathing pulse** (connected, waiting for first byte), not tier-colored.

## Model Speed Trends (metrics.rs `model_stats` + src/model_stats.ts)

- **Entry & Layout**: the **segmented toggle** at the right side of the chart card head (`#chart-view-toggle`; "Overall Chart / Model Details" text on left and right, light-cyan block slides to the active side — same color as the dropdown selected state, no solid highlight) **exclusively switches** between the two views; the model view is embedded inside the chart card (legend chips + per-model lines + stats rows), no longer a popup. View selection saved to localStorage (`chartView.v1`, default: Overall Chart), remembered across restarts. Active period fetches every 5s and redraws with wall-clock phase translation every 1s; when collapsed to floating window, main is hidden and fetching auto-skips (auto-restores when returning to full panel).
- **Stats range shares the same dropdown as the overall chart** (15 min / 1 hour / 6 hours / 24 hours, `chartRange.v1` remembers): switching the toggle only swaps the series, **doesn't change the stats time range**; when the range changes the model view immediately re-fetches (`refresh()`). The frontend passes current range and grid interval via `getRange()` (single source of truth is `CHART_RANGES` in main.ts).
- **Bucket granularity**: exactly the same spec as the overall chart — unified 90 buckets, `bucket_ms = window ÷ 90` (15min→10s, 1h→40s, 6h→4min, 24h→16min); bucket index = `now ÷ bucket_ms − completed_at ÷ bucket_ms` (div_euclid, **absolute wall-clock slot alignment**, same spec as chart_stats / today's spark: bucket boundaries pinned to integer multiples of real time; two queries in the same slot have identical bucket contents — trends only translate over time without deformation); 0 = newest bucket, 89 = oldest; out-of-bounds (including future cross-slot) discarded; buckets with no calls have tps = 0.
- **Per-model line**: bucket tps = Σ(output+reasoning) ÷ Σ pure-generation seconds; gen_ms spec matches the global (`completed_at − first_token_at`; first_token missing or non-positive falls back to `duration_ms`, lower bound 50ms). y-axis 0~`niceCeil(peak×1.25)` (same quantization spec as the overall chart; small data changes don't cause the whole line to vertically rescale; 3 horizontal grid lines + labels); x-axis uses the **exact same mapping** as `gauges.drawSpark` — right edge = next wall-clock bucket boundary, grid lines at integer-minute intervals (same as overall chart: 5min / 10min / 1h / 4h) + right edge "Now HH:MM", directly cross-checkable against data; the two views' x-axes align pixel-perfectly, grid stays put when toggling. Line colors cycle through an 8-color palette in order; model names > 18 chars are truncated with … (full name in title).
- **Per-model stats row**: model name + `Avg (full-window Σeff ÷ Σgen_s) · Peak (max bucket tps) · Calls · Tokens (=Σeff, with share = this model eff ÷ all-model eff)`; series sorted by total_tokens descending.
- **Legend chip multi-select**: each model has a self-drawn chip (color dot + name, dark button style); click toggles that model's visibility — line and bottom stats row filtered in sync; chip color takes the model's original index in the full list (re-showing keeps the color); **at least one required**: deselecting all reverts to all-selected. Legend trailing has two small text buttons: "Select All" and "Top 3 only" (top 3 by total_tokens; equivalent to all-selected when fewer than 3 models). Selected set persisted in localStorage (`modelStats.visible.v1`, stores visible model name array; falls back to all-selected if not found / all models no longer exist; during 5s poll refresh the selected set stays in memory, newly-appearing models default to visible and aren't silently hidden by old archives).
- **Data source & zero storage**: directly read-only queries the `model_usage` table in `~/.zcode/cli/db/db.sqlite` (`status='completed' AND completed_at >= now − window`); Rust computes aggregation live, memory-caches the last result; **creates no indexes / writes to that DB and adds no new local storage**. The frontend only fetches every 5s via `invoke("model_stats", { windowMin })` while the toggle is on the model view (windowMin = current range); switches away → clearInterval. Browser preview (no Tauri) uses `mock.mockModelStats` to compute simulated data with the same spec.
- **Tests**: `aggregate_model_stats` is a pure function (`metrics.rs`); two-model two-bucket aggregation, window clamp, gen_ms fallback, and **wall-clock alignment guard** (two `now` queries in the same absolute slot have identical bucket contents field-by-field — regression guard: previously buckets were assigned by `(now − completed)` relative offset, so bucket boundaries drifted with query time, causing the line to micro-deform every tick) each have unit test guards.

## Auto-Start (autostart.rs)

The second section of the settings popup (top-bar ⚙), alongside "Visible Modules", three-state radio: **off** (disabled, default) / **boot** (launch at login, displays in the last mode recorded in `~/.zcode/speed-panel-mode.txt`) / **follow** (silent standby after login, shows panel when ZCode is detected). **Registry / plist is the single source of truth** — no local config file is written; the UI reads back the real state every time it opens; hand-editing the registry or deleting the plist truthfully reverts to off (`AutostartMode::parse` treats unknown values as Off), avoiding state drift between two locations.

| Platform | Target | Content |
|---|---|---|
| Windows | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value name `zcode-speed-panel` | REG_SZ = `"<exe full path>" [--zcode-follow]` (quoted so portable editions moved to paths with spaces aren't truncated; no admin needed; `winreg` is a Windows-only dependency) |
| macOS | `~/Library/LaunchAgents/com.zcode.speedpanel.autostart.plist` | Hand-written XML (no plist dependency): `ProgramArguments` = exe + (when following) `--zcode-follow`, `RunAtLoad=true`; off = directly delete the file |

- **Follow mode**: auto-start command line carries `--zcode-follow`; `main.rs` setup skips `window.show()` when it sees this argument (only the tray stays resident, no window shown), and starts a detection thread — first sleeps 3s to avoid the login rush, then calls `liveio::platform::any_zcode_process()` every 2s; on hit, calls `show_main` and exits the thread (once shown, never auto-hides). The panel **won't auto-resurrect after manual exit** (recovers on re-login or manual open) — the natural boundary of the single-instance architecture, stated in the settings UI.
- **Process determination spec** (`any_zcode_process()`, liveio.rs platform sub-module): Windows uses Toolhelp32 enumeration matching **process name `zcode.exe`** — **intentionally doesn't read the command line**; the desktop shell and CLI child processes share the same name; a name hit counts, faster and broader than `discover_cli_pids`; macOS matches `KERN_PROCARGS2` argv[0] ending with `/ZCode` (desktop) or parameter area containing `zcode-cli` (CLI, same spec as `discover_cli_pids`).
- **Relationship with single-instance**: `--zcode-follow` only takes effect when no instance exists at boot — a parameterized launch hitting an existing instance is intercepted by `tauri-plugin-single-instance` and routed to the wake-up callback to directly show the old window, so a manual second launch won't be misjudged as silent standby.
- **Frontend**: three rows reuse `settings-row` + `.pet-chk` self-drawn checkbox (radio semantics); write failure shows inline error and rolls back the selected state; popup adds `max-height` + scrolling to prevent small-screen overflow; browser preview (no Tauri) is display-only (not writable).
- **Tests**: `parse_roundtrip` (three states + unknown value → Off) and Windows `registry_enable_disable_cycle` end-to-end (real HKCU read/write; restores original value after test, no side effects).
- **Boundary**: the macOS branch (plist write and `any_zcode_process` KERN_PROCARGS2 determination) **only passes `cargo check`, not verified on-device** — LaunchAgent directly executes the binary inside `.app` rather than going through `open -a`; whether the app identity and Dock two-state behavior match manual launch needs on-device confirmation; the Windows-side registry three-state and follow wake-up have been verified on-device.

## Logging System (main.rs DebugLog)

- `~/.zcode/speed-panel-debug.jsonl`: JSONL append, 8MB rotates to `.jsonl.1`; rotated files older than 7 days auto-deleted at startup.
- Four event types: `tick` / `call` / `cal` (format and troubleshooting in [key-rules.md](key-rules.md) #6) and `cal_reset` (manual / drift auto recalibration: `reason`=manual/auto, coefficient before/after `bpt_old`/`bpt_new`; auto also attaches trigger-time round average `round_avg` and 5-round baseline `base_avg`). Also `net` events (netio.rs, see "Network Monitoring" section): `ev`=ckpt_accepted / ckpt_upload_start / ckpt_upload_end, with workspace `ws`, artifact size `mb`, and whether backfilled `backfill`.
- `tick` also includes the **multi-task troubleshooting trio**: `infl` (in-progress session count), `pids` (detection-window cleaned rate per tracked process, KB/s), `attr` (last 4 chars of in-progress session → attributed pid list). When multi-task display is abnormal, reconcile these three first: which process in `pids` is writing, whether `attr` is squeezing two sessions into the same pid, and whether `infl` matches the gate (2026-09-18 troubleshooting only had the single `npids` field, couldn't answer "which process is writing"). `tick` also includes the **network monitoring quintet**: `net_up` / `net_dn` (machine-wide upload/download rate, KB/s), `cli_conn` / `app_conn` (session group / desktop group connection count), `ckpt_up` (snapshot upload in progress).

## In-App Update (updater.rs)

- **Version number**: sourced from `tauri.conf.json`'s `version` (same value across three places: `Cargo.toml` / `package.json`, bumped together for release); runtime reads `app.package_info().version`. Full panel status bar far right shows it (e.g. `v0.2.1`; hidden in floating window / pet form and browser mock mode); **click to manually check for updates** — checking shows a spinning ↻ prefix; result fed back as a bottom-right toast ("Already up to date vX.Y.Z" / "Update check failed: network error").
- **Check timing**: ① 8s after startup (avoiding startup SQLite/IO peak) one silent background check; ② hourly wake during residency, only fires if ≥ 24h since last successful check (once per day); ③ manual version number click. Data source: GitHub API `repos/Masterchiefm/zcode-speed-panel/releases/latest` (must carry User-Agent; latest endpoint naturally excludes draft/prerelease; 403 rate-limit handled same as network failure).
- **Silent principle**: any failure on the auto path (offline, rate limit, parse failure, no installer for this platform, unparseable tag) is treated as "no update", no popup no toast — better to miss than to disturb. The only truthful feedback scenario: download / installer launch failure after the user clicked "Update Now" (silence would make the button appear broken).
- **Version comparison**: `parse_version` takes the tag's `v?major.minor.patch` three-segment numeric value (`-rc.1` / `+build` suffixes ignored; this project doesn't ship pre-releases); strictly greater than current version counts as an update; either side parse failure doesn't count (prevents weird tags from inducing updates).
- **Installer matching (CI naming coupling, key-rules #12)**: win-x64 → `*_x64-setup.exe` (NSIS installer; portable edition doesn't participate in auto-install); mac-x64 → `*_x64.dmg`; mac-aarch64 → `*_aarch64.dmg`. Changing build.yml product names / adding architectures requires syncing `updater::pick_asset` and its tests in the same commit.
- **Flow**: new version detected → emit `update`(available) → bottom-right update card popup (old vs new version comparison + Release notes summary + "What's New ↗" link via `open_url` command opening in system browser; only https allowed + **"Manual Download ↗" button** — self-service path besides in-app install; opens this version's Release page for manual download; falls back to releases list page when no version URL) → immediately **silent background pre-download** to system temp `zcode-speed-panel-update/<asset-name>` (progress throttled to 250ms emit downloading event) → on ready emit ready, card button changes to "Install Now". Clicking "Update Now" when not yet downloaded marks it pending; auto-installs on ready, no second click needed.
- **Install**: Windows runs the NSIS installer, saves state and exits the app 600ms later (installer takes over; delayed exit avoids hitting the process lock); macOS `open` opens the dmg for the user to drag into Applications (app doesn't exit; old version runs until user restarts). Installation is **user-click triggered** rather than fully automatic unattended — an installer window popping up unprompted conflicts with the "don't disturb" principle, and silent replacement of unsigned packages is risky; if fully automatic is desired in future, add `/S` to the Windows installer launch (NSIS silent install); the download/ready chain doesn't need changes.
- **Don't-disturb details**: after the card's ✕ is closed, that version won't auto-pop again (frontend localStorage remembers; a small blue dot stays next to the version number as a reminder; manual check reopens the card); in floating-window mode the card / toast isn't shown (still visible when returning to full panel); pre-download failure when the user isn't waiting for install is fully silent (clicking "Update Now" re-triggers the download).

## CI & Release

- `.github/workflows/build.yml`: **not auto-triggered by normal pushes**; a `v*` tag → auto-creates a GitHub Release, Assets include Windows installer (`_x64-setup.exe`), portable (`_x64-portable.exe`, main exe renamed), and macOS dual-architecture dmg (`_x64.dmg` = Intel 10.15+, `_aarch64.dmg` = Apple Silicon 11+; independent packages, not universal; unsigned/notarized — see README bypass guide); `workflow_dispatch` → manually triggered from the Actions page; artifacts in that run's Artifacts (`windows` contains two exe; `macos-x86_64-apple-darwin` / `macos-aarch64-apple-darwin` each contain one dmg).
- **Release flow (in-app update dependency, key-rules #12)**: version number bumped in three places — `src-tauri/tauri.conf.json` (authoritative: read at runtime for display and comparison), `src-tauri/Cargo.toml`, `package.json` — then tag `v*`. Update check matches installers by Release asset name suffix (see "In-App Update" section); build.yml product naming can't be changed arbitrarily.
- **build-macos job**: `runs-on: macos-15`, matrix dual targets (`x86_64-apple-darwin` + `MACOSX_DEPLOYMENT_TARGET=10.15`, `aarch64-apple-darwin` + `11.0`), tauri-action `--bundles dmg`; minimum system version double-injected — env var decides the binary `LC_BUILD_VERSION`, `--config '{"bundle":{"macOS":{"minimumSystemVersion":"…"}}}'` decides Info.plist `LSMinimumSystemVersion` (plist only recognizes config, default is always 10.13, doesn't read env var). Product names `zcode-speed-panel_<version>_x64.dmg` / `_aarch64.dmg` by tauri default naming, exactly satisfying the dual independent package requirement.
- Local release build: `npm run tauri build` → Windows `src-tauri/target/release/bundle/nsis/*.exe`; macOS `bundle/dmg/*.dmg` (cross-build aarch64 see README dev section).

## Known Boundary Cases

- Silent-pipe calls (measured ~half) use ≈ fallback for real-time readings, expected behavior not a bug (these calls first show the 20s "…" prompt at startup then switch).
- Multi-task concurrency (multiple windows / sub-agents in parallel): real-time reading is the **aggregated total throughput of in-progress sessions' attributed processes** (falls back to all-process sum when any session has no attribution record); the full panel simultaneously shows per-task details (see "Real-Time Speed" section). Multiple sub-agents in the same process can't be split at the byte level and display as that process's combined total.
- After cold start the coefficient needs 1–2 qualifying calls to converge; readings may be off before that.
- Network monitoring spec boundaries (see "Network Monitoring" section for detail): **session traffic is a token×coefficient order-of-magnitude estimate** (± several times, labeled ≈); **snapshot artifacts are the true lower bound of the panel's observation period** (accepts while the panel isn't running are only backfilled once on first start of the day); **machine-wide numbers mix other apps' traffic** and include tunnel encryption overhead when going through a local proxy; connection attribution is Windows-only. When the checkpoints directory is ACL-locked it shows "Unreadable" and new uploads can't be monitored (the lock itself is user-side protection).
- Hard crash (CLI process killed, assistant row with no one to backfill `completed`) leaves the gate for up to 10 minutes (safety-net upper bound); process exit for an attributed session is immediately force-stopped by the process guard; new unattributed sessions can only wait for the safety net.
- In mac's CleanParams (burst disabled / no static noise floor / coefficient prior 700 / delayed disk-write grace 15s / outlier rejection 3x), the prior and grace have been corrected per the 2026-09-17 6-cal-event true-value reconciliation (when attribution is correct, pred/true match exactly 62.1=62.1); an equal-length reconciliation regression hasn't been done for the Windows side; when readings run abnormal, first run `python scripts/live_vs_true.py` to reconcile, then look at cal event `attr_pid` / `top_pid` attribution before tuning parameters (key-rules #10).
- In-app update capability **takes effect per version**: only users who installed a version containing updater.rs will receive subsequent update prompts; existing older versions need one manual upgrade to lay the groundwork; dev instances (`npm run tauri dev`) also do real checks and downloads — when the version equals the latest Release tag it shows "Already up to date", expected (hot restart triggers a startup check each time, volume far below API rate limit).
